# F：资产规划输入与运行信息边界

本工作包把“用什么资料决定资产”变成实际执行路径。默认保留原有全窗口规划行为，
但输出明确标为 oracle；固定资产与事前规划均以固定容量调度运行实况。
本文中的规划模式、设计情景和信息可用时点均为 **S（场景先验）**。
守恒和运行约束由 F 数值核负责，本控制器不增加气象或电力物理公式。

## 1. 三种执行路径

| 模式 | Stage12 线路选择/修改 | Stage13 储能选址/初步容量 | 设计期联合扩容 | 运行期容量 |
|---|---|---|---|---|
| `fixed_assets` | 跳过 | 配置明确指定站点；默认空集 | 跳过 | 冻结，四类扩容变量均为零 |
| `preplanned` | 独立设计源荷 | 独立设计源荷 | 在设计窗口完成 Stage14 扩容 | 冻结设计所得全部资产 |
| `full_window_planning` | 完整运行窗口源荷实况 | 完整运行窗口源荷实况 | 与运行调度联合决定 | oracle 联合优化 |

固定资产不运行旧的天气驱动选址函数。事前规划先用同一静态世界生成独立设计天气与源荷，
完成线路、储能和联合容量设计，再读取运行源荷进行固定容量调度。运行末小时需求的变化
不能改变前两种模式的设计输入或资产哈希。全窗口模式明确允许这些改变。

## 2. 事前设计场景

事前天气共享地形、水文、长期气候、土地和已有母线。该共享反映同一合成区域的环境，
不共享运行天气、运行源荷序列或其随机数状态。

设计随机种子为 `derive_module_seed(world_seed, "planning:" + design_seed)`，然后建立独立
`build_rng_registry`，分别读取 `weather`、`weather_hourly` 和 `source_load` 流。
原有模块的随机数消耗顺序不变。元数据保存实际派生种子和设计种子参数。

设计使用独立 `WeatherConfig` 和 `SourceLoadConfig`，由各自默认值加规划专属覆盖项构造，
不会暗中继承运行天气或运行源荷配置。`design_config_snapshot` 保存展开后的全部参数。
`design_days` 和 `design_start_day_of_year` 明确定义设计时轴。

设计 timestamps 是独立的 365 日气候年索引，不是过去观测日期。元数据声明
`planning_time_axis=independent_design_climatology_not_operation_clock`，并把输入可用时点
单独记录为 `planning_information_available_at_operation_hour`。两个独立气候年的数值时间
不互相比大小；缓存检查输入可用边界不晚于运行起点。这里的“事前”是实验信息边界，
不能据此宣称设计情景是现实未来的无偏预测。

## 3. 配置

新增独立 `PlanningConfig`，旧 `StorageConfig` 继续定义优化/运行参数。

| 配置 | 单位/默认 | 作用 |
|---|---|---|
| `mode` | `full_window_planning` | 实际规划路径 |
| `design_days` | 日，7 | 独立设计长度 |
| `design_start_day_of_year` | 从 0 开始的日，0 | 独立设计季节 |
| `design_seed` | 非负整数，190731 | 设计随机流命名参数 |
| `design_weather_overrides` | 字典，空 | 独立天气配置覆盖项 |
| `design_source_load_overrides` | 字典，空 | 独立源荷配置覆盖项 |
| `fixed_storage_sites` | 站点列表，空 | 固定站点 ID、bus ID、MW、MWh、可选初始 SOC 比例 |
| `line_faults` | 事件列表，空 | 支路 ID、相对运行起点小时、持续小时 |

错误模式、非法 ID、非正容量、非法设计时间和故障时长在配置阶段拒绝。
固定站点只能用于 `fixed_assets`，不在其他模式中静默忽略。
站点 ID 与事件支路 ID 必须存在；事件不能超出完整运行时轴。

## 4. 源荷与资产接口

Stage11 保存原始可用发电、计划发电和请求负荷，不被规划覆盖。
控制器按持久 bus ID 对齐运行源荷与规划后的母线，新增中转母线填零；
删除仍承载非零源荷的母线直接拒绝。

当事前设计改变火电名牌容量时，将 Stage11 的每小时可用量和计划量乘以
`installed_nameplate / original_nameplate`，保留每小时可用比例。
这是 **S + 工程简化**：新增同类机组与原机组共享同一可用率，不表示独立机组故障模拟。
有 E 附录时，原容量只读明确名牌字段，不能用运行窗口最大出力反推。
旧无名牌数据仅保留绝对可用功率，不推断扩容可用比例。
运行对齐数组保持 float64，并先求原可用比例再乘安装容量，防止 float32 原地缩放
把满可用功率舍入到精确安装容量之上。满可用比例 1 精确对应安装容量，停机比例 0
仍对应零；原输入超过其声明名牌容量则拒绝，不在对齐中裁剪掩盖。

Stage9 的火电土地台账按持久 thermal bus ID 传入设计和运行优化。
初始容量超过预留地容量上界时拒绝；后续扩容受同一上界约束。

## 5. 冻结资产和初始状态

`data/planning/initial_assets.npz` 保存规划前资产，`frozen_assets.npz` 保存安装后资产。
快照包含母线 ID/容量、电气参数、支路 ID/额定值、储能站点位置/MW/MWh、
配置先验 SOC 和火电土地上界。哈希按排序键、dtype、shape、连续字节计算，
不依赖 NPZ ZIP 文件时间戳。数值采用与既有 Stage12/13 矩阵相同的 float32 导出精度，
避免缓存读写的表示精度变化被误报为资产干预。

D 土地台账保留 float64 面积计算上界。恢复时若 float32 容量恰为该上界的最近舍入值，
且上溢不超过半个 float32 ULP，运行对象恢复为台账的精确上界；原缓存不改写。
这只纠正可验证的导出舍入来源，不放宽核的土地约束。相邻 float32 数或其他 float64
超限均拒绝，不能以“数值容差”掩盖实际超用。

SOC 是边界库存，不属于永久资产。快照中的 `storage_initial_soc_mwh` 特指配置先验，
用于记录实验边界，不代表周期调度求得的初始 SOC。
非周期运行把各站点该值显式传入核；固定站点自设比例不会被全局默认比例覆盖。
周期运行声明 `initial_state_policy=optimized_periodic_runtime`，不传固定初态，
实际周期起点由运行窗优化求出。设计期求得的周期初态不会伪装为已知运行初态。

## 6. 故障和运行可见性

故障只生成 `[T,E]` 的 `branch_in_service`，保留全部支路 ID 和永久资产。
设计情景不接收运行故障时段。运行核按各时段有效拓扑求岛内平衡。
恢复读取相同事件配置和时轴，不能随机重抽故障。

所有三种模式当前都允许调度器看到完整运行窗口，输出声明
`dispatch_foresight=full_operation_window_perfect_foresight_dispatch`。
冻结资产不等于在线控制；本版不能用于证明无未来信息控制器的性能。
运行期重新计算 `storage_need` 仅作为脆弱性诊断，不能重新决定固定或事前规划站点。

## 7. 缓存、输出和兼容

保留 Stage11 原源荷、Stage12 检查点、Stage13 计划及 Stage14 四个结果文件与可视化入口。
事前设计输入另存 `planning/design_input/`，设计结果另存 `planning/design_result/`。
主 `metadata.json.asset_planning` 与 `planning/asset_boundary.json` 保存相同权威边界声明。
设计输入和两个资产文件均有内容哈希，恢复验证文件、ID、时轴及哈希。

固定/事前规划从 Stage13 恢复时复用已冻结的站点，不依据缓存运行周重新选址。
因旧 storage 配置同时包含容量、初态和运行参数，本版对这两模式的 storage 配置变化
统一要求从 Stage1 重新建立可审计边界。oracle 保留从 Stage13 修改储能配置的路径。
缺少 F 信息边界的旧缓存不能混入现代恢复流程；通用历史数据读取仍由接口层兼容。

## 8. 验证和边界

定向控制器测试使用真实调度核，并以可响应设计源荷的最小规划器检验因果边界：

- 固定模式禁止调用天气驱动规划函数；未来负荷增加可导致缺供，但资产哈希不变。
- 事前模式的独立设计哈希、冻结哈希不随运行未来改变，原完整运行时轴保留。
- oracle 同一未来扰动会改变设计输入和线路资产，证明三模式不是仅更换标签。
- 显式站点初始 SOC、周期初态语义、单时段故障及持续 ID 均通过解析检查。
- 内容哈希独立于字典顺序，篡改容量会被缓存拒绝；配置 dump/load 等价。

集成中另复现并修复了两项导出精度反例：土地饱和的 220.5274611711502 MW
被 float32 导出成 220.5274658203125 MW，以及事前扩容后可用功率的 float32 原地乘法上溢。
独立核阈值保持不变。修复后的定向测试为 32 项通过；原 oracle seed42 从 Stage14
恢复通过 335 项世界检查，24 小时事前设计/运行场景及其 Stage13 恢复各通过 334 项检查。
事前恢复前后设计输入、初始资产、边界文件及冻结资产内容哈希一致，站点 ID 保持 `[0,1,2]`。

本版不模拟多年投资时序、施工延迟、跨情景随机规划或滚动在线调度。
单一独立设计场景会漏掉其他季节和联合极端，独立不代表充分代表性。
建议后续扩展为事前多季节情景集合和有明确预测接口的滚动调度；本版不以此延迟
固定、独立事前和 oracle 三种可执行信息边界的交付。
